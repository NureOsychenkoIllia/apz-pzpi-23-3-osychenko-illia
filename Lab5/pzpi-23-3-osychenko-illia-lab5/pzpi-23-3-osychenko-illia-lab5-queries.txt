=== Запит 1: Структура підсумкового звіту та презентації

Назва інструменту та версія: Claude Code (claude-sonnet-4-6)

Мета використання: Визначення структури підсумкового звіту лабораторної роботи №5 та порядку висвітлення компонентів системи в презентації на основі матеріалів лабораторних робіт №1–4.

Внесок автора: Автор самостійно визначив склад компонентів системи та їх пріоритетність для презентації, критерії розподілу функцій на «виконані» та «не виконані» на підставі реального стану реалізації. Перевірив відповідність запропонованої структури вимогам завдання.

Початковий запит:

«На основі матеріалів лабораторних робіт №1–4 курсу APZ склади структуру підсумкового звіту та Marp-презентації (14–15 слайдів) для лабораторної роботи №5. Звіт має містити короткий опис проекту, заплановані та виконані функції, посилання на відео та матеріали презентації. Стиль: безособово, без жирного тексту в основному тексті, без надмірних списків.»

Відповідь: Запропоновано структуру звіту з розділами «Завдання», «Опис виконаної роботи» (опис системи + таблиця заплановано/виконано) та «Висновки», а також додатки: відеозапис, слайди, запити до ШІ. Для презентації запропоновано 15 слайдів із тематичними блоками за кожною лабораторною роботою та підсумковим слайдом.

Уточнення:

«Як коректно оформити розділ "заплановано та виконано", якщо частина компонентів реалізована в межах суміжного курсу (ATRK), а не поточного (APZ)?»

Відповідь: Компонент IoT ESP32 варто включити до таблиці зі статусом "Виконано (курс ATRK)" — це відображає реальний стан системи без приховування джерела реалізації. Функції, заплановані у Vision & Scope (Lab 1) але нереалізовані (iOS, ШІ-модуль), фіксуються зі статусом "Не виконано" або "Заплановано в наступних релізах" відповідно до характеру причини.

=== Запит 2: UML-діаграма розгортання всієї системи

Назва інструменту та версія: Claude Code (claude-sonnet-4-6)

Мета використання: Побудова зведеної UML-діаграми розгортання BusOptima, яка охоплює всі чотири компоненти (IoT ESP32, Android, Web, Server) на одному рисунку для слайда архітектури.

Внесок автора: Автор самостійно визначив склад вузлів, напрями потоків даних, назви компонентів відповідно до реальної архітектури системи. Перевірив відповідність діаграми специфікації UML після генерації PNG.

Початковий запит:

«Згенеруй PlantUML deployment-діаграму для системи BusOptima: вузли IoT-клієнт (ESP32, інфрачервоні датчики + HTTP), Android-клієнт (Kotlin/Compose), Веб-браузер (React/TS), Серверна частина (Nginx + 3 репліки Go/Fiber + PostgreSQL 17 + backup_data volume). Стрілки: IoT → Nginx, Android → Nginx, Web → Nginx (REST/HTTP); Nginx → api1/api2/api3; api1-3 → PostgreSQL; api1-3 → backup_data.»

Відповідь: Згенеровано PlantUML-файл із чотирма вузлами верхнього рівня, вкладеними компонентами в межах вузла "Серверна частина" та відповідними стрілками-залежностями. Діаграма відповідає стандарту UML Deployment Diagram та конвертована в PNG командою plantuml -tpng architecture.puml.

Уточнення:

«Як на deployment-діаграмі показати, що IoT-клієнт реалізований в межах іншого курсу, але є частиною загальної системи?»

Відповідь: Достатньо додати позначку "(ATRK, ESP32)" у підпис вузла або у нотатку (note) поряд з вузлом. Це не порушує коректності UML-діаграми, але дає контекст рецензенту без введення окремої легенди.

=== Запит 3: Дизайн Marp-презентації

Назва інструменту та версія: Claude Code (claude-sonnet-4-6)

Мета використання: Налаштування CSS-стилізації Marp-презентації: кольорова схема, типографіка, стиль таблиць, темний титульний слайд, нумерація сторінок, футер.

Внесок автора: Автор самостійно визначив кольорову схему (темно-синій `1a3a5c` + блакитний `4a90d9`), перелік кастомізацій та наклав обмеження на розмір зображень (max-height для вписування в слайд). Перевірив результат після рендеру через `npx @marp-team/marp-cli`.

Початковий запит:

«Напиши CSS-блок для Marp-презентації: темно-синій заголовок із синьою рискою знизу, клас `section.title` для титульного слайда (темний фон `1a3a5c`, білий текст), стиль таблиць з темним th, футер із розміром 0.5em, paginate: true. Усі зображення з max-height та автоматичним центруванням.»

Відповідь: Згенеровано CSS-блок у полі style Marp frontmatter з усіма запитуваними властивостями. Клас `section.title` застосовується через директиву `_class: title` на першому слайді. Нумерація сторінок активована глобально через `paginate: true`.

Уточнення:

«Як уникнути відображення шрифту через Google Fonts у середовищі без доступу до мережі під час рендеру PNG?»

Відповідь: Директиву `@import` з Google Fonts можна залишити у CSS — браузерний рушій Marp CLI просто проігнорує запит до мережі та відпаде до системного шрифту (Arial або Helvetica). Для повної детермінованості рендеру слід замінити `@import` на пряме оголошення font-family без зовнішнього посилання.

=== Запит 4: Написання звіту

Назва інструменту та версія: Claude Code (claude-sonnet-4-6)

Мета використання: Написання академічного звіту лабораторної роботи №5 у форматі Typst відповідно до стилю попередніх лабораторних робіт курсу.

Внесок автора: Автор самостійно визначив зміст кожного розділу звіту, обсяг опису кожної лабораторної роботи та формулювання для таблиці "заплановано/виконано". Перевірив відповідність тексту шаблону попередніх лабораторних та стилістичним вимогам (безособово, без жирного тексту, без надмірних списків).

Початковий запит:

«Напиши звіт лабораторної роботи №5 у форматі Typst (шаблон з `#import "template/lib.typ"`): безособово, без жирного тексту в основному тексті, мінімум списків. Тема: "Презентація готового проекту BusOptima". Розділи: Завдання (з умови), Опис виконаної роботи (короткий опис системи + 4 підрозділи за лабораторними + таблиця виконаного), Висновки. Додатки: відеозапис (placeholder), слайди презентації (15 PNG через `#slide-img`), запити до ШІ.»

Відповідь: Написано повний звіт із розділами Завдання, Опис виконаної роботи та Висновки. Розділ "Опис виконаної роботи" містить чотири підрозділи за компонентами системи та підсумкову таблицю заплановано/виконано. Додатки включають відеозапис із placeholder-посиланням, 15 слайдів через макрос slide-img та файл запитів до ШІ.

Уточнення:

«Як у розділі "заплановано та виконано" коректно описати IoT-компонент, що реалізований в суміжному курсі, а не в поточному?»

Відповідь: У таблиці у стовпці "Статус" зазначити "Виконано (курс ATRK, ESP32)" — такий запис точно описує реальний стан без двозначності. У тексті звіту вказати, що IoT-клієнт реалізовано поза межами даної лабораторної роботи, проте є невід'ємним компонентом кінцевої системи BusOptima.
